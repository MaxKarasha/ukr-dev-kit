# Як долучитися

Дякуємо, що хочете зробити ukr-dev-kit кращим. Найцінніше — нові правила, хибні спрацювання й
приклади реальних текстів, на яких інструменти помиляються.

## Нове правило вичитки

Правила — прості текстові файли в `skills/ukr-proofread/rules/`:

| Файл | Що там |
|---|---|
| `surzhyk.txt` | російські слова й форми |
| `calque.txt` | кальки зворотів |
| `style.txt` | правопис 2019, скорочення |
| `term.txt` | ІТ- й UI-терміни |

Один рядок — одне правило:

```text
ключ | рівень | шаблон | заміна | пояснення
```

- **рівень:** `error` — явна помилка; `warning` — найімовірніше помилка, але є законні вживання; `hint` — стиль.
- **шаблон:** регулярний вираз Python без урахування регістру. Межі слова додаються самі, пробіл означає
  «будь-які пробіли», альтернативи — через `|` без пробілів довкола. Охопіть потрібні відмінкові форми.
- **заміна:** текст підказки; якщо починається з `=`, це шаблон заміни (`=\1\2`), і правило
  виправляється автоматично через `--fix` — лише для однозначних випадків.
- **пояснення:** чому це помилка й як правильно — його бачать користувачі в `--explain`.

Перед тим як надіслати:

1. Перевірте, чи слово не має законного українського значення (як «удалий», «заказник», «протяг»).
   Якщо має — зробіть шаблон точнішим або оберіть рівень `warning`.
2. Додайте тест у `tests/test_lint.py`: приклад, який правило ловить, і приклад, який не повинно.
3. `python3 -m unittest discover -s tests` — усе зелене, зокрема тест на чистому тексті `tests/fixtures/good.txt`.

## Код

- Лише стандартна бібліотека Python 3.10+ — жодних залежностей у скриптах скілів
  (виняток — оточення HolosTTS, яке ставиться окремо).
- Повідомлення, довідка CLI й документація — українською.
- Скрипт має працювати й сам по собі, і як інструмент агента: зрозумілі помилки, код виходу, `--format json`.
- Зміни в SKILL.md — коротко й по суті: агент читає їх щоразу. Деталі виносьте в `references/`.

Перевірки перед PR:

```bash
python3 -m unittest discover -s tests
python3 tools/validate_skills.py
python3 tools/check_validators.py        # потрібні Node 22+ і .NET для TypeScript і C#
python3 skills/ukr-proofread/scripts/ukr_lint.py README.md CONTRIBUTING.md skills/*/SKILL.md skills/*/references
```

## Випуск нової версії

Claude Code кешує плагін за номером версії: без нової версії користувачі не отримають змін.

1. `python3 tools/bump_version.py X.Y.Z` — версія за [SemVer](https://semver.org/lang/uk/) зміниться в маніфестах
   плагіна, пакеті Python і скриптах скілів (CI перевіряє, що вона всюди однакова).
2. Додайте розділ у `CHANGELOG.md`, оновіть `rev:` / `@vX.Y.Z` у прикладах README.
3. Після злиття в `main` і зеленого CI: `git tag -a vX.Y.Z -m "…" && git push origin vX.Y.Z`.
   Workflow `Release` сам перевірить тег і опублікує пакет на PyPI.
4. `gh release create vX.Y.Z` з нотатками з CHANGELOG.

## Повідомлення про помилку

Додайте вхідний текст чи файл, команду й те, що ви очікували побачити. Для озвучки — рушій
(`ukr_voice.py doctor`), голос і текст.

## Поведінка

Будьмо доброзичливими: різні погляди на мовні норми — привід для аргументованої розмови з посиланням
на правопис чи словник, а не для суперечки.
